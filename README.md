# ScRl — школьная экономика

ScRl — серверное приложение школьной экономики на чистом Node.js, без внешних npm-зависимостей.

## Запуск

Требуется Node.js 18 или новее. Для обычного локального тестирования задайте `SCRL_DEMO_MODE=true`; демо-аккаунты отключены по умолчанию.

```bash
npm start
```

По умолчанию приложение доступно по адресу http://localhost:3000. Порт можно изменить переменной окружения `PORT`.

Проверка синтаксиса всех JavaScript-модулей и встроенные тесты:

```bash
npm test
```

Проверка синтаксиса всех JavaScript-модулей:

```bash
npm run check
```

## Основные разделы

### Ученик
- Главная и кошелёк ScRl с историей операций.
- Единая доска публикаций с фильтрами «Мне нужно» и «Я могу».
- Подбор активных предложений помощи по точному совпадению категории с собственными запросами; бесплатные варианты отображаются первыми.
- Единый раздел активности: входящие и отправленные отклики, сделки и сообщения.
- Сделки с блокировкой ScRl в escrow для платных условий.
- Отметка выполнения, подтверждение покупателем, возврат/выплата по внутреннему ledger-сценарию.
- Переписка внутри сделки, отзывы после завершения.
- Избранное, жалобы, профиль и уведомления.
- Внутренняя биржа с двумя направлениями обмена: ScRl за V-RUB и V-RUB за ScRl.
- Рыночная цена ScRl рассчитывается по семидневному VWAP исполненных сделок; администратору доступны свечной график, обеспеченный лимит, покрытие, динамическая комиссия и настройка целевого курса.

### Учитель
- Кабинет и начисление ScRl в рамках недельного лимита.

### Администратор
- Монитор и пользователи.
- «Пульс лицея»: агрегированная аналитика завершённой помощи, бесплатных договорённостей, скорости отклика, запросов без ответа и категорий с нехваткой предложений. Учитель видит только свой класс, администратор — весь лицей; имена и тексты запросов в отчёте не раскрываются.
- Единая очередь проверок Demand/Offer, Marketplace и споров по сделкам.
- Жалобы с категориями и деталями на объявления Marketplace и Demand/Offer.
- Повторное сканирование уже опубликованного контента; отмеченные публикации скрываются до ручного решения.
- Сверка escrow по конкретной сделке/заявке, действия модератора и журнал аудита.
- Локальный помощник модератора с аналитикой текущих данных; он не выносит автоматические решения.
- Financial Operations с журналом платёжных заявок и состоянием платёжного модуля.

## AI-модерация

Поддерживается серверная проверка новых публичных публикаций в Demand Board, Offer Board и Marketplace, а также повторное сканирование уже опубликованных объявлений. Модель возвращает только один из двух вердиктов:

- `keep` — публикация остаётся видимой;
- `review` — публикация скрывается со статусом ожидания и попадает в очередь ручной проверки администратора.

Локальные правила работают параллельно. Они не могут быть отменены вердиктом модели. Если внешний ИИ включён, но запрос не удался, модель вернула некорректный ответ или квота закончилась, новая публикация направляется на ручную проверку.

Интеграция использует GigaChat через OAuth и OpenAI-совместимый endpoint. Модель по умолчанию — `GigaChat`; её можно изменить через `SCRL_GIGACHAT_MODEL`.

Для подключения задайте в Environment основного веб-сервиса Render:

- `SCRL_AI_MODERATION_ENABLED=true`
- `SCRL_GIGACHAT_AUTH_KEY` — секретный ключ авторизации GigaChat
- `NODE_EXTRA_CA_CERTS=/opt/render/project/src/certs/russian_trusted_root_ca_pem.crt` — доверенный корневой сертификат для TLS GigaChat (в репозитории хранится только публичный сертификат, не секретный ключ)

В модель передаётся очищенный текст объявления без отдельной передачи имени, класса, email, учётной записи или ID пользователя. Email, ссылки, телефоны, платёжные/идентификационные номера, адресные фрагменты и @-упоминания маскируются, но автоматическая очистка не гарантирует удаление абсолютно всех персональных сведений из свободного текста.

Внешняя обработка пока выключена по умолчанию и не включается без действующего ключа. Не подключайте школьные данные несовершеннолетних к внешнему сервису до проверки школьных правил, согласий и политики хранения данных ответственным взрослым. Не отправляйте через этот модуль приватную переписку, жалобы, пароли, документы или медицинские сведения.

API-ключ нельзя помещать в Git, HTML, клиентский JavaScript или логи. Если ключ был опубликован в переписке или другом открытом месте, его нужно отозвать и создать новый.
## Настройка администратора и безопасность

Для production задайте переменные окружения `SCRL_ADMIN_EMAIL` и `SCRL_ADMIN_PASSWORD` (не менее 12 символов). При старте ScRl создаст отдельную учётную запись администратора или обновит пароль уже существующей админ-учётки с этим email. Этот email не должен принадлежать обычному пользователю. Не храните пароль в Git и не используйте пароль из демо-режима.

Пароли хранятся с индивидуальной солью и scrypt; старые SHA-256 хэши постепенно обновляются при успешном входе. Сессии имеют серверный срок действия; POST-запросы проверяют Origin/Referer и ограничены по размеру тела (64 КБ).

## Внутренний курс и RUB

V-RUB — внутренняя учебная единица, а не реальные рубли. Рыночная цена ScRl рассчитывается как VWAP фактически исполненных сделок за последние 7 дней: суммарный объём V-RUB делится на объём ScRl, участвовавший в исполненных обменах: для покупки ScRl учитывается выданный покупателю объём после комиссии, для покупки V-RUB — ScRl, уплаченные покупателем. При отсутствии сделок используется целевой курс (по умолчанию 0,05 V-RUB за 1 ScRl).

Обеспеченный лимит обращения = V-RUB участников / целевой курс. Учитываются доступные и заблокированные ScRl участников; системный резерв ещё не выпущен и не считается обращением, сожжённые ScRl исключены. Новые начисления из системного резерва блокируются, если превысят обеспеченный лимит. При покрытии ниже 100% комиссия сжигания ScRl равна 0,5% + (1 − покрытие) × 20 процентных пунктов, но не выше 20%. При покрытии от 100% до 200% она линейно снижается до 0%. Это внутренний механизм виртуальных единиц, не реальное денежное обеспечение и не обещание выкупа.

Биржа работает в обе стороны внутри ledger: покупка ScRl оплачивается V-RUB, покупка V-RUB оплачивается ScRl. Перед каждой сделкой проверяются доступные остатки, средства продавца резервируются, а отмена заявки возвращает их владельцу. Отрицательные балансы запрещены проверкой ledger.

## RUB и платежи

Переменная окружения `SCRL_PAYMENTS_MODE` принимает:
- `disabled` (значение по умолчанию) — платёжный модуль не подключён;
- `sandbox` — можно создавать тестовые заявки, но реальные деньги не переводятся и ScRl не начисляются по факту тестовой заявки.

Реальные пополнения и выводы не реализованы без юридического допуска, договора и интеграции с уполномоченным партнёром. RUB Auction, денежные ставки и денежные призы не являются частью утверждённой спецификации. Ставки аукционов — только ScRl; призы — неденежные.

Встроенный помощник модератора анализирует агрегаты локально. Внешняя проверка объявлений — отдельный выключенный по умолчанию механизм, который можно включать только после проверки школьных правил обработки данных несовершеннолетних.

## Структура

- `scrl.js` — точка входа.
- `src/server.js` — HTTP-сервер и маршрутизация.
- `src/config.js` — настройки и путь к данным.
- `src/store.js` — файл данных, совместимое расширение старой схемы, счета и транзакции.
- `src/security.js` и `src/session.js` — безопасность и сессии.
- `src/utils/http.js` — HTTP/HTML-функции.
- `src/views/` — общая дизайн-система, темы и шаблон страницы.
- `src/features/` — модули авторизации, ученического кабинета, маркета, аукционов, сделок, уведомлений, модерации, аналитики пользы и финансов.
- `src/services/impact-metrics.js` — расчёт агрегированных метрик взаимопомощи без идентификации учеников.
- `src/services/board-matching.js` — безопасные рекомендации активных предложений по совпадающей категории запроса.

Данные сохраняются в корневой файл `scrl-data.json`, который не добавляется в Git. Новые коллекции автоматически добавляются к старому файлу данных без удаления существующих записей.

## Интерфейс

- Светлая и тёмная темы, выбор запоминается в браузере.
- Desktop: компактная верхняя навигация по главным разделам; общая доска объединяет спрос и предложения, активность — отклики и сделки.
- Кошелёк доступен с главной страницы, уведомления открываются через значок колокольчика.
- Биржа поддерживает обмен ScRl и V-RUB в обе стороны; ученикам не показывается служебный резерв токенов.
- Администратор видит рыночную цену, целевой курс, обеспеченный лимит, покрытие, динамическую комиссию и свечной график; реальные RUB не подключены, V-RUB остаётся симуляцией.
- Планшеты: адаптивные сетки и таблицы с горизонтальной прокруткой.
- Учитываются системная настройка уменьшения анимации и safe-area мобильных устройств.
